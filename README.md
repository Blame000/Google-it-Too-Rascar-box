# Извлечение поз и трекинг

Основа всего пайплайна — качественные данные о движении бойцов. Для этого используется модуль, адаптированный из бейзлайна соревнования, который автоматически извлекает позы из сырых видео с помощью компьютерного зрения.

## Детекция и трекинг

**Модель:** YOLO11m‑pose — обеспечивает оптимальный баланс между скоростью и точностью определения 17 ключевых точек (голова, плечи, локти, кисти, бёдра, колени).

**Трекинг:** Модель работает в режиме `track` с параметром `persist=True`, что позволяет сохранять идентификаторы бойцов между кадрами и отслеживать их движение во времени.

**Целевые объекты:** Фильтр `classes=[0]` оставляет только класс _person_, игнорируя рефери, углы ринга и зрителей.

# Распределение ролей (Color-based Role Assignment)

YOLO не знает, кто из бойцов относится к красному углу, а кто — к синему. Чтобы стабильно различать их, используется динамическая венгерская ассоциация.

### Цветовой анализ

Для каждого обнаруженного человека вырезается полигон торса (по keypoints плеч и бёдер). В HSV‑пространстве вычисляются доли красного (`red_score`) и синего (`blue_score`) цветов.

### Матрица затрат

Строится матрица, где каждый трек сравнивается с ролями **RED** и **BLUE**. Чем выше цветовой скор, тем ниже стоимость назначения.

### Memory‑фактор

К цветовому скору добавляется 40% «памяти» — расстояние до предыдущего положения бойца этой роли. Это стабилизирует назначение при перекрытиях, резких движениях и смене ракурса.

### Венгерский алгоритм

Алгоритм `linear_sum_assignment` оптимально назначает каждому треку уникальную роль с минимальной суммарной стоимостью.

**Результат:** каждый кадр содержит строго двух бойцов с устойчивыми метками `fighter: red` или `fighter: blue`.

# Выходные данные (Raw Poses)

Для каждого кадра и каждого бойца сохраняется:

-   временная метка: `frame`
    
-   идентификаторы: `video_key`, `track_id`, `fighter`
    
-   bounding box: `x1`, `y1`, `x2`, `y2`
    
-   17 ключевых точек: `kp_{i}_x`, `kp_{i}_y`, `kp_{i}_c` для `i = 0..16`
    

**Формат хранения:** Apache Parquet — быстрый доступ и минимальный размер.

**Объём:** около 130 000 записей (кадр × боец) для тестового набора.

# Post‑processing в build_dataset.ipynb

После получения сырых поз строится итоговый датасет для обучения модели детекции ударов.

### Нормализация

Восстанавливаются относительные координаты keypoints относительно центра и высоты бокса.

### Скорости

Через `groupby().diff()` вычисляются:

-   мгновенная скорость (`speed`)
    
-   ускорение (`accel`)
    

для кистей, локтей и других ключевых точек.

### Оппонентные фичи

Для каждого бойца подтягиваются данные второго бойца:

-   `opp_center_x`, `opp_head_x`
    
-   `opp_left_wrist_speed` и другие динамические признаки
    

Это позволяет учитывать взаимодействие бойцов.

### Геометрия

Вычисляются расстояния:

-   от кисти до головы оппонента
    
-   между центрами бойцов
    
-   между ключевыми точками
    

### Скользящие окна

Для скоростей кистей считаются:

-   `mean_5`
    
-   `max_5`

чтобы модель видела локальные всплески активности.

# Построение модели

##  Общая логика пайплайна

Пайплайн начинается с загрузки покадровых данных и метаданных о видео. Каждый кадр содержит координаты бокса, keypoints, размеры, скорости и множество других параметров. Эти данные сами по себе ещё не дают модели понимания динамики — поэтому основной упор сделан на генерацию фичей, которые превращают сырые координаты в осмысленные признаки движения.

Далее обучается ансамбль из CatBoost, XGBoost и LightGBM — три разных бустинга, которые компенсируют слабости друг друга. После обучения детектор применяется к тестовым данным, вероятности сглаживаются, и по ним извлекаются пики — кандидаты на удары. Затем подбирается порог. На финальном этапе обучаются модели атрибутов удара, и формируется итоговый submission.

----------

#  Загрузка обучающего и тестового датасета

Пайплайн начинается с загрузки трёх ключевых источников данных:

-   **train.parquet** — обучающий набор, содержащий покадровые данные и метку удара
-   **test.parquet** — тестовый набор с такой же структурой, но без метки
-   **videos.csv** — метаданные о каждом видео
----------

Обучающий набор загружается из файла train.parquet в структуру, тестовый — из test.parquet, а метаданные о видео — из videos.csv. Эти три источника дополняют друг друга: первые два содержат покадровые признаки, а третий — информацию о самом видео. Сразу после загрузки пропуски в данных заменяются нулями, чтобы модели не сталкивались с отсутствующими значениями. Затем обучающий и тестовый наборы объединяются с метаданными по ключу `video_key`, и каждый кадр получает контекст: к какому видео он относится, какой это раунд, сколько всего кадров в ролике, каковы размеры изображения и какой боец изображён.

## Признаки

Самая важная часть пайплайна — это feature engineering. Именно он превращает набор координат в полноценное описание движения бойца. 

### **Нормализация keypoints**

Координаты keypoints приводятся к относительным значениям:

-   относительно центра бокса,
    
-   относительно высоты бокса.
    

Это позволяет модели понимать позу бойца независимо от его размера, положения в кадре и масштаба видео. Например, положение кисти относительно корпуса — куда важнее, чем абсолютные пиксели.

### **Позиционные признаки кадра**

Каждый кадр получает:

-   нормированный индекс (от 0 до 1),
    
-   синус и косинус этого индекса.
    

Это помогает модели учитывать цикличность движений и ритм боя.

### **Временные признаки (prev/next/diff)**

Для каждого числового признака вычисляются:

-   значение на предыдущем кадре,
    
-   значение на следующем,
    
-   разности между ними.
    

Это даёт модели ощущение «скорости изменения» любого параметра — от положения локтя до расстояния между бойцами. Удар — это всегда резкое изменение, и такие признаки помогают его уловить.

### **Rolling‑фичи**

Для скоростей, расстояний и ускорений считаются:

-   средние значения,
    
-   стандартные отклонения
    

по окнам 3, 5, 7 и 9 кадров.

Эти признаки описывают локальную динамику движения: насколько стабильно или резко меняется положение частей тела. Удары обычно выделяются всплесками скорости и нестабильностью.

### **Скорости keypoints**

Для ключевых точек (кисти, локти, плечи, голова) вычисляется скорость:
```
speed = sqrt(dx² + dy²)
```

Это один из самых сильных признаков: удар почти всегда сопровождается резким ускорением кисти.

##  Hard Negative Mining

Чтобы модель не путала удары с похожими движениями (например, защитой или шагом вперёд), используется hard negative mining. В обучающий датасет включаются:

-   все настоящие удары,
    
-   отрицательные примеры рядом с ударами,
    
-   случайные отрицательные примеры.
    

Это делает модель более избирательной и устойчивой к ложным срабатываниям.

## Ансамбль моделей

Для детекции используется ансамбль из трёх бустингов:

-   **CatBoost** 
    
-   **XGBoost** 
    
-   **LightGBM**
    
Финальная вероятность — взвешенная сумма трёх предсказаний.

##  Извлечение событий

После получения вероятностей:

1.  они сглаживаются скользящим окном,
    
2.  на них ищутся пики,
    
3.  каждый пик уточняется по необработанной вероятности,
    
4.  применяется NMS, чтобы убрать дубликаты.
    

Так формируется список кандидатов на удары.

## Классификация атрибутов удара

Для каждого найденного события обучаются отдельные модели CatBoost, которые предсказывают:

-   какой рукой нанесён удар,
    
-   куда он пришёлся,
    
-   какой это тип удара,
    
-   был ли он результативным.
   

Эти модели обучаются только на положительных примерах.
